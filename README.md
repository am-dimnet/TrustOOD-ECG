# TrustOOD-ECG Reproducibility Package

This directory contains the English-only code, configuration, environment, and
de-identified reference outputs needed to reproduce the revised TrustOOD-ECG
study:

> TrustOOD-ECG: Reliability-Gated Dirichlet Fusion for Rare-Class ECG Analysis
> and Out-of-Distribution Risk

The package covers raw waveform cache construction, deterministic label and split
construction, feature extraction, model training, calibration, OOD evaluation,
wearable LOSO evaluation, reviewer-requested extensions, statistical aggregation,
and independent result audits.

## Reproducibility boundary

This package does **not** contain raw PTB-XL, Chapman-Shaoxing, MHEALTH, or WESAD
data. It also excludes checkpoints, record-level predictions, patient or subject
identifiers, credentials, and private infrastructure metadata. Obtain each raw
dataset from its official source and comply with its licence and access terms.

The included `reference_outputs/` directory contains only de-identified aggregate
summaries and completion audits. These files are useful for checking a rerun, but
they are not substitutes for the record-level outputs required to recompute every
bootstrap analysis.

## Data preparation

### PTB-XL and Chapman-Shaoxing

`code/build_waveform_cache.py` closes the raw-WFDB-to-cache step. It creates:

| File | Contract |
|---|---|
| `ptbxl_signals.npy` | `(21799, 12, 1000)`, `int16`, microvolts, source CSV order |
| `chapman_signals.npy` | `(45152, 12, 1000)`, `int16`, microvolts, sorted WFDB-header order |
| `ptbxl_meta.csv` | PTB record, patient, demographic, device, fold, and validity fields |
| `chapman_meta.csv` | Chapman record, demographic, and validity fields |
| `preprocess_manifest.json` | source paths, dimensions, failure counts, software, SHA-256 |

The PTB-XL 100-Hz records are read directly. Chapman 500-Hz records are reduced to
100 Hz using a zero-phase FIR decimator and cropped or padded to 1,000 samples.
Physical millivolts are converted to clipped int16 microvolts. Existing caches are
never replaced without `--force`.

The canonical cache identities used by the reported experiments are:

| Artifact | Bytes | SHA-256 |
|---|---:|---|
| `ptbxl_signals.npy` | 523,176,128 | `1e42e9381fbd165fe4b4855ceff56611d46ddeb272f32791ca51aa974d4c7798` |
| `chapman_signals.npy` | 1,083,648,128 | `90cb30ae5a6d65f2e5e130105446188bbf130cbe4c82a8e0f1b78ad9012937c6` |
| `ptbxl_meta.csv` | recorded in the cache manifest | `f250b92a3994bcc5c8827fa29ce3ff12c6b28cf7240a3bc06b4ee955d1b0382f` |
| `chapman_meta.csv` | recorded in the cache manifest | `78a15347a93237f1a2404afa3f017cc6d70057191b36906e25648e8c3b6b515d` |

A newly downloaded official release or a different WFDB/SciPy stack can change
serialized bytes. In that case, retain the new manifest and require all scientific
row-count, order, shape, split, and validity audits to pass before training.

`code/data_adapter.py` then performs the authoritative row-order and patient-split
audits and creates the compact experiment sidecars:

- deterministic 70-class single-label surrogate labels;
- original multi-label SCP-code sets;
- strict OOD partitions for `tau = 40, 80, 160`;
- SQI6 and scalar quality;
- HRV8;
- 36 spectral features;
- source and output SHA-256 manifests.

The waveform arrays are opened read-only with NumPy memory mapping. Only requested
batches are converted from int16 microvolts to float32 millivolts.

### MHEALTH and WESAD

The formal wearable runner uses one NPZ per subject. The included preprocessing
programs create that interface from the official archives:

```bash
python code/wearable_preprocessing/preprocessing/prep_mhealth.py \
  --dir /path/to/MHEALTHDATASET \
  --out /path/to/wearable/mhealth

python code/wearable_preprocessing/preprocessing/prep_wesad.py \
  --zip /path/to/WESAD.zip \
  --out /path/to/wearable/wesad
```

WESAD contains Python pickle objects. Only deserialize an archive obtained from a
trusted official source and verified before use.

The canonical combined input hashes are
`5e84934fccb378749f7c23d64bcbbf938ad2a6bc0e8b41c834b2fc58eeb266a4`
for MHEALTH and
`59a2c267ed2903e7477c4f99eca38036c9dc0601d4d8784cedf2374ac0940348`
for WESAD. Per-subject hashes and shapes are retained in
`configs/wearable_input_manifests/`.

## Fixed experimental protocols

### PTB-XL

- Official `strat_fold` 1-8: training.
- Fold 9: validation, temperature fitting, score normalisation, coefficients, and
  fixed operating thresholds.
- Fold 10: final evaluation.
- The rare-class definition is training-fold surrogate-label support below 50.
- Canonical comparisons use seeds `7, 13, 42, 99, 2026`.
- Focused ablations use seeds `7, 42, 2026` unless explicitly declared otherwise.

The strict semantic OOD protocol defines held-out non-baseline raw SCP codes by
training-fold presence below `tau`. Every training or validation record containing
a held-out code is purged. Fold-10 OOD records are reported as pure, mixed, and all
OOD. The formal thresholds are `40`, `80`, and `160`.

Chapman is used only as cross-dataset OOD after PTB-XL fitting. No Chapman example
fits a feature standardiser, covariance, temperature, score normaliser,
coefficient, or threshold.

### Wearable LOSO

- MHEALTH: subjects `S1-S10`, activity labels 1-12 mapped to 0-11.
- WESAD: subjects `S2-S11` and `S13-S17`, affect labels 1-4 mapped to baseline,
  stress, amusement, and meditation.
- The held-out subject is the test fold.
- The next subject in the fixed circular order is validation.
- All remaining subjects are training.
- Formal seeds are `7, 42, 2026`.

## Formal experiment matrix

| Matrix | Output contract |
|---|---:|
| Base PTB-XL | 212 JSON/raw/OOD result triplets, 252 model fits, 25 launcher tasks |
| MHEALTH and WESAD LOSO | 345 JSON/prediction pairs, 75 launcher tasks |
| Canonical noise/SQI | 3 seed bundles, 3 workers |
| PTB reviewer extensions | 221 JSON/raw/OOD triplets, 66 launcher tasks |
| Gate architecture extension | 9 result/checkpoint pairs, 9 tasks |
| Noise-shift calibration | 3 inference-only seed pairs |
| Modular pipeline | 8 inference workers: 5 PTB and 3 noise |

Across all formal matrices, the archived run accounts for 189 task processes,
801 result records, and 854 neural fits. The fit count comprises 252 base PTB fits,
345 wearable fits, 27 canonical noise/SQI fits, 221 PTB extension fits, and 9 gate
extension fits. Noise-shift calibration and the modular pipeline are inference-only.

The base PTB main methods are `trust_full`, `softmax_modular`,
`concat_matched`, `deep_ensemble`, `tmc`, `tmdf`, `pool_only`, and `fuse_only`.
The historical experiment tag `tmdf` denotes the official ETMC implementation.

## Execution order

After preparing the caches and sidecars, the formal dependency order is:

```bash
bash code/run_ptbxl_matrix.sh
bash code/run_noise_sqi_matrix.sh
bash code/run_wearables_matrix.sh
bash code/run_ptbxl_missing_matrix.sh
bash code/run_noise_gate_matrix.sh
bash code/run_noise_shift_calibration_matrix.sh
bash code/run_modular_pipeline_matrix.sh
```

The noise-shift and modular analyses require canonical noise checkpoints and
results. The modular PTB workers require canonical `softmax_modular` PTB outputs.
Extension audits require the base PTB results for exact split and label alignment.

Smoke runs may be used to test the remote pipeline, but smoke outputs must never
be combined with formal results.

## Aggregation and audits

The core PTB aggregator verifies the expected method/protocol/seed matrix,
configuration, fingerprints, file hashes, raw-array schema, OOD score schema, and
metric completeness before calculating summary statistics. Missing cells are never
imputed.

The included audits independently validate:

- all 212 base PTB result triplets;
- all 345 wearable outputs and 3 canonical noise outputs;
- all 221 PTB extension triplets;
- all 9 gate extension cells;
- all 3 noise-shift calibration cells;
- all 8 modular pipeline cells.

Only outputs for which the relevant `--fail-on-incomplete` command returns zero
should be used in publication tables.

## Integrity verification

Run:

```bash
python verify_package.py
```

The verifier checks the exact file inventory, SHA-256 digests, absence of symbolic
links, absence of CJK text, and exclusion of record-level/model binary artifacts.
`SHA256SUMS` covers every other file in this directory.

## Reference outputs

`reference_outputs/aggregates/` contains the verified aggregate summaries used to
cross-check a new run. `reference_outputs/manuscript_tables/` contains the four
English machine-readable supplementary tables. Historical absolute paths inside
some reference manifests are provenance only; they are not required deployment
paths.

Exact floating-point identity across different GPU, driver, CUDA, cuDNN, BLAS, and
compiler stacks is not guaranteed. Use the recorded deterministic settings and
compare the statistical summaries with appropriate numerical tolerance.

After reproducing the aggregate directory structure, compare its stable scientific
tables with the references:

```bash
python code/compare_reproduction.py \
  --candidate-root /path/to/new/aggregate \
  --reference-root reference_outputs/aggregates \
  --rtol 1e-5 --atol 1e-7
```

This comparison deliberately excludes timestamps, machine paths, hashes, and other
run-specific provenance. Strict completeness audits must pass before this numerical
comparison is interpreted.
